# 角色称呼的语音误识别容错

已确认的转写变体：はるき→晴樹／晴树，羽那→花，霧子→桐子，恋鐘→小金。

`name_recognition.py` 按当前角色提供共同的称呼说明，由 `judge.turn_state` 交给独立或检索合并的判断模型，由 `engine._prompt` 交给回复模型。原始输入、聊天历史不替换；“花”等普通词和明确谈及其他人仍按上下文理解。这些变体不会加入语音热词，以免强化错误写法。

如果整句只有当前角色的上述变体及首尾空白、常见标点，`engine._reply` 在生成情绪、结束判断和保存好感之前，将已有评分置为中性。带其他词的句子仍正常判断，避免名字被用来绕过对实际辱骂、威胁和操纵的处理。这一小范围保护同时覆盖文字和通话，以及开启或关闭检索的路径；不会追溯修改旧评分。

热词另外补入 `name_kana` 中以空白分开的名字部分，例如“はるき”；单字及服务商长度限制继续保留。热词只提高识别机会，不能保证转写服务永不出错。

回归测试在真实文字回合路径中注入错误的越界判断，确认单独“小金！”不扣分、不注入生气情绪；另覆盖四位角色变体、原话保留、普通词义、包含侮辱或指令的句子及其他角色隔离。没有用真实付费模型重放历史误判；较长句子的上下文理解仍需实际使用观察。
