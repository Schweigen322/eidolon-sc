# 站内主动消息

在「设置 → 档案 → 主动消息」配置。默认关闭、未选择任何角色，不会调用模型。
开启后由当前部署的聊天模型生成，使用部署者服务和计费，不读取浏览器自带密钥。

- 从选中的、已有未结束对话的角色中轮流选择；冷却、封禁、未同意条款时不发送。
- 所有角色共用发送间隔（2–72小时）和每日尝试上限（1–5次，默认2次）。失败也计入。
- 安静时段按设置时区计算，支持跨午夜；起止相同表示不设安静时段。
- 保存设置后重新等待一个间隔。服务未启动时不发送，恢复时不补发积压消息。
- 同一角色已有主动消息而用户未回复时，不再继续发送。阅读不等于回复。
- 不打断当前通话或文字生成，用户最近15分钟聊过时暂缓。
- 生成期间设置、当前对话或历史发生变化时丢弃旧结果；失败不立即重试。
- 消息只保存真实的角色发言，不伪造用户输入，不影响好感度，不自动生成语音或照片。
- 网页可见时约30秒刷新，列表显示「新消息」，打开对话标为已读。不调用手机系统通知。
- 后台每分钟检查一次；发送不是精确到秒的定时提醒。每位角色最多等待一条未回复消息。

内容依据角色人设、该用户的导入档案及当前对话最近12条消息。不会全量读取其他角色聊天，
不把生成出来的「日常」当成已确认的现实行踪；不执行额外剧情检索或付费批量评测。
日语练习邀请没有新用户日语输入，不进行凭空纠错。

数据库新增 `proactive_settings`、`proactive_attempts`，与原业务表共用数据卷。
尝试先持久登记再请求模型，服务重启不会重试同一条；用户删除时一起清除。
删除历史对话不会留下可读取的消息正文，尝试计数保留到用户删除，避免通过删消息绕过每日次数。

接口均需当前用户登录：`GET/PUT /api/proactive`。角色列表摘要可含 `unread_proactive`。
读取对话消息会将该对话的主动消息标为已读。
